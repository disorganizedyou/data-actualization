# Актуалізація даних для медичної служби — версія 2

Два самодостатні HTML-файли без залежностей і без мережі:

| Файл | Для кого | Що робить |
|---|---|---|
| `dist/anketa.html` | Медики підрозділів | Покрокова анкета; перевіряє дані; віддає **повний звіт PDF** (і чернетку PDF). Плаката тут немає. |
| `dist/medsluzhba.html` | Медична служба | Відкриває звіти PDF підрозділів, показує їх стан і потреби, друкує **плакати A4** («Довідка чергового»), усі плакати одним файлом, зведення контактів чергових і зведення потреб усіх підрозділів. |

Обидва файли працюють з `file://` (Downloads на Android, «Файли» на iPhone, будь-який ПК). Нічого нікуди не надсилається.

## Як користуватися

**Підрозділ.** Відкрити `anketa.html` → пройти 9 кроків → на кроці «Перевірка та звіт» виправити все червоне, підтвердити зауваження → «Завантажити звіт PDF» → надіслати черговому медслужби **лише через Element**. Наступного разу — «Відкрити PDF» і завантажити попередній звіт (або чернетку): дані підставляться, лишиться оновити дату й те, що змінилося. Звіти попередніх версій форми теж відкриваються: дані переносяться автоматично, а форма попросить дозаповнити нові поля (для версії 1 — НРК, гіпотермія, хімзахист; для версії 2 — чи здійснюють скиди інші підрозділи; для версії 3 — медичні пункти).

**Медслужба.** Відкрити `medsluzhba.html` → перетягнути всі отримані PDF → «Плакат» біля підрозділу або «Усі плакати одним PDF» → друк. «Зведення потреб» збирає потреби всіх підрозділів в один PDF. Кнопка «Деталі» показує потреби й зауваги підрозділу без відкриття PDF. Плакат із чернетки або звіту з помилками друкується лише після підтвердження й отримує червону позначку.

**Чернетки й робоча копія.** Чернетка PDF — єдиний надійний спосіб зберегти незавершену анкету. Додатково браузер тримає робочу копію на пристрої до 2 днів (де сховище доступне); вона стирається після завантаження звіту або кнопкою «Очистити». Імена файлів — латиницею (`Zvit_med_2MB_2026-10-30.pdf`), бо кирилиця в іменах завантажень ненадійна в частині браузерів і месенджерів.

## Розробка

```bash
npm run build   # збирає dist/anketa.html і dist/medsluzhba.html
npm test        # юніт-тести (node --test)
npm run e2e     # наскрізний тест у Chromium (Playwright має бути встановлений)
```

Node.js ≥ 22, залежностей немає. Для `e2e` потрібен Playwright (`npm i -g playwright` або встановлений у `/opt/node-tools`). Версія збірки (у футері звіту) — `v2-` плюс 7 знаків хешу вихідних файлів; вона змінюється лише коли змінюється код.

Сторонній код — лише `vendor/pdfmake.min.js` (pdfmake 0.3.13) і шрифти e-Ukraine; їх версії, джерела та SHA-256 — у `vendor/MANIFEST.json`, збірка звіряє хеші й падає при розбіжності. Після навмисного оновлення файла: `node build/build.mjs --update-manifest`.

### Структура

```
src/shared/   схема даних (schema.mjs), валідація (validate.mjs), кодек PDF (codec.mjs),
              побудова звіту (report.mjs) і плаката (poster.mjs), помічники pdfmake (pdfkit.mjs)
src/form/     анкета: app.mjs, form.css, index.html
src/med/      інструмент медслужби: app.mjs, med.css, index.html
build/        build.mjs — склеює модулі, інлайнить pdfmake + шрифти, ставить CSP з хешами
vendor/       pdfmake 0.3.11 (min), шрифти eUkraine (OTF)
test/         юніт-тести;  e2e/roundtrip.mjs — Playwright
docs/         REQUIREMENTS.md (вимоги й рішення), REVIEW.md (рев'ю старої версії та зміни)
```

Модулі — звичайні ES-модулі (щоб їх тестував Node), але в `dist` вони склеюються в один класичний `<script>`: збірка прибирає `import`/`export` і перевіряє синтаксис результату. Правила: лише іменовані експорти, унікальні імена на верхньому рівні між усіма модулями (збірка перевіряє), імпорти тільки відносні.

### Як змінити поля анкети

Усе описано в `src/shared/schema.mjs`: додайте поле в потрібний розділ або групу точки (`POINT_GROUPS`) — форма, валідація, звіт і плакат підхоплять його автоматично (у плакат потрапляє лише те, що явно вказано в `poster.mjs`). Якщо змінюється сенс наявних ключів — підніміть `SCHEMA_VERSION` і допишіть міграцію в `codec.mjs → migrate()`.

### Як дані живуть у PDF

Звіт містить дані анкети двічі: вкладений файл `data.json` (стандартний механізм PDF) і рядок `FormData` у метаданих (Info) з контрольною сумою. Будь-яка з двох копій достатня для відкриття у формі. Читання захищене від великих сторонніх PDF (лінійний пошук) і від «бомб стиснення» (ліміт 512 КБ на розпаковані дані). Деталі й міркування безпеки — у `docs/REVIEW.md`.

## Розповсюдження

У групу надсилається тільки `dist/anketa.html`. `dist/medsluzhba.html` — внутрішній інструмент медслужби. Після кожної зміни коду запускайте `npm run build` і надсилайте новий файл (версія збірки видна у футері звіту).
