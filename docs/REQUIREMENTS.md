# Вимоги до версії 2 (зафіксовано 31.10.2026)

Джерело: запит медичної служби + уточнення в діалозі.

## Контекст

- Анкету (HTML-файл) розсилають у групу WhatsApp. Медики підрозділів завантажують файл, відкривають на телефоні чи комп’ютері й заповнюють по своєму підрозділу.
- Результат роботи підрозділу — **повний звіт PDF**. Його повертають **виключно через Element** черговому медслужби (правило лишається, попри розсилку анкети через WhatsApp).
- **Плакат A4** («Довідка чергового») друкує для себе медслужба. Підрозділи плакат генерувати **не повинні** — тому генерація плаката винесена в окремий файл для медслужби.

## Що треба було зробити

1. **Повністю новий дизайн форми**, спланований з нуля, з найзручнішим форматом заповнення (телефон у пріоритеті).
2. **Звіти** — лишити в тому ж вигляді, з точковими покращеннями.
3. **Нові дані** для кожної точки передачі поранених:
   - НРК (наземний роботизований комплекс): чи є; якщо є — кількість, чи обладнані РЕБ, камерою, мікрофоном.
   - Засоби проти гіпотермії: хімічні грілки, спальники, Ready-Heat.
   - Засоби індивідуального захисту (хімзахист).
4. **Ревʼю коду та безпеки** попередньої версії.
5. Анкета має **не давати пропустити важливі поля** і **робити звірки** формату даних: завантаження звіту повністю заблоковане, поки є помилки (рішення: повна заборона, без кнопки «все одно завантажити»).

## Рішення, ухвалені в діалозі

| Питання | Рішення |
|---|---|
| Де живуть дані про НРК | У картці кожної точки передачі (не окремий розділ, не підсумкові кількості) |
| Де генерується плакат | Окремий файл `medsluzhba.html` для медслужби; в анкеті плаката немає |
| Канал передачі звіту | Лишити «виключно через Element» |
| Медичні пункти (схема v4) | Крок «Медичні пункти» об’єднує чергового медпункту та список медпунктів; «Формування скидів медпунктом» — на кроці «Медичні скиди» (разом 7 кроків). Список (хоча б один), для кожного — назва, координати MGRS, позивний начальника та його контакти (WhatsApp / Signal / Element / Discord або «Немає», хоча б один). Є у звіті й на плакаті |
| Вичитка тексту (схема v3, див. `TEXT_AUDIT.md`) | Внесено всі правки аудиту, крім: підпис «Час підльоту…» лишається; пояснення «Частково» поки не додаємо; Element лишається третім у списку месенджерів. «Забезпечення» + «потреба» об’єднано в одне питання; додано питання «чи скидають інші»; старі звіти мігрують автоматично |
| Блокування завантаження | Повна заборона до усунення всіх помилок; широкий набір обов’язкових полів (загальні дані, усі контакти чергових або «Немає», для кожної точки — назва, координати, зв’язок, інтернет, забезпеченість майном, НРК, гіпотермія, хімзахист, підготовка; усі так/ні-відповіді; пояснення, коли відповідь негативна) |

## Обмеження середовища

- Один самодостатній HTML-файл на кожен інструмент, без мережі (працює з `file://`, з Downloads на Android, з «Файлів» на iPhone).
- Шрифт eUkraine і бібліотека pdfmake вбудовані у файл.
- Старі PDF-звіти (версії 1 і 2) мають відкриватися в новій формі.

## Зроблено понад вимоги (можна прибрати, якщо зайве)

- Робоча копія анкети у сховищі браузера (2 дні, стирається після звіту) — щоб не втрачати введене на телефоні.
- Чернетка PDF з водяним знаком — щоб зберегти незавершену анкету й продовжити пізніше.
- В інструменті медслужби: «Усі плакати одним PDF», «Зведення контактів чергових», «Зведення потреб», перегляд потреб і зауваг у «Деталях».
- Перехресні звірки (дата, дублікати, суперечності забезпечення, НРК «Частково» за одного) з обов’язковим підтвердженням зауважень.
